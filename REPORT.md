# Краткий отчёт: постобработка OCR паспорта РФ

## Подход

Решение представляет собой консервативный фильтр поверх готовых OCR-предсказаний; новую нейросеть не обучаем, потому что задача предоставляет распознанные поля, confidence и MRZ. Принимаем документ только при прохождении всех проверок, иначе просим переснять.

Добавлены проверки форматов полей, действительности паспорта на 01.10.2026, структуры MRZ, контрольной цифры даты рождения и номера документа, совпадения фамилии/имени с MRZ, кодов подразделений и геометрии длинных текстовых полей. Проверка срока действия следует п. 24 Положения о паспорте гражданина РФ, утверждённого Постановлением Правительства РФ от 23.12.2023 № 2267: паспорт действует до 20 лет, затем до 45 лет, после 45 лет бессрочно; после достижения 20/45 лет действует не более 90 календарных дней. Источник: https://www.consultant.ru/document/cons_doc_LAW_466454/6125ca6a5baabbd3bbff7302f6c6e114b94061fa/

## Эксперименты

| Версия | Принято на train | Ошибочных принятий по полям | Принято на test |
|---|---:|---:|---:|
| Исходный baseline | 127 / 3000 | 6 | 163 / 2000 |
| Консервативная версия | 109 / 3000 | 0 | 135 / 2000 |

Ошибки исходной версии включали три ошибки фамилии, одну ошибку имени, одну ошибку места рождения и одну неполную строку органа выдачи. Confidence не всегда отражал эти ошибки: встречались неверные значения с confidence 1.0. Поэтому добавлены независимые проверки MRZ и геометрии текстовых полей. Один дополнительный MRZ-шаблон был добавлен после анализа тренировочной ошибки; это эвристика для предоставленного набора, а не универсальное правило.

## Прогноз для test

Ожидаемое число принимаемых документов по текущему алгоритму: **135 из 2000** (6,75%). Точечный прогноз числа ошибочно принятых — **0**, поскольку после уточнения правил в тренировочной диагностике ошибок среди 109 принятых не осталось. Однако это оптимистичная оценка: правила дорабатывались по train, поэтому независимой проверки риска нет. Фактическое число ошибок на test неизвестно без скрытых меток. Перед использованием результата как надёжного прогноза необходима нетронутая validation-выборка.

## Ограничения

- `evaluate.py` проверяет совпадение полей, но сам не проверяет действительность паспорта; для этого добавлен `validate_train.py`.
- MRZ тоже может быть распознана неправильно, даже при высокой confidence; совпадение двух OCR-выходов не является гарантией.
- Текущая эмпирическая таблица соответствий кириллицы и MRZ специфична для предоставленных данных.
- Нулевое число ошибок на train не гарантирует нулевой риск на test. Система сознательно отклоняет много документов, чтобы уменьшить вероятность ошибочного принятия.
